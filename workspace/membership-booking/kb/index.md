# Knowledge Base — Project: Athlete Membership & Booking

> Shared knowledge for this project. Every task inherits this context; task-level
> knowledge (in each task's `kb/`) takes precedence where the two overlap.

## Summary

Programme to build a membership platform where people join a tier, book in-store
and community **experiences**, and earn/redeem reward points. This KB holds the
durable business context, the agreed vocabulary that reconciles the inconsistent
naming used across raw inputs (sessions / classes / events → **Experience**), the
tier model, the shared personas, and the running **decision log** that later tasks
inherit so settled questions are not re-opened. See `context.md` for full context.

## Entries

- `context.md` — durable project context: business goals, domain terms,
  constraints, assumptions. Downstream skills consult this before re-asking.
- `glossary.md` — canonical domain terms; reconciles inconsistent input naming.
- `tiers.md` — membership tier model (Free / Plus / Premium) and what is open.
- `personas.md` — shared personas and their goals/pains (used by every task).
- `decisions.md` — running log of settled cross-task decisions. **Task 002 reads
  this to avoid re-opening questions task 001 already closed.**
