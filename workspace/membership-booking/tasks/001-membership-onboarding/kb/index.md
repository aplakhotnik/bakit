# Knowledge Base — Task: Membership Onboarding

> Task-scoped knowledge. Supplements the project KB and takes precedence where the
> two overlap. Most context for this task lives at the project level (`../../kb/`);
> this file only records what is specific to onboarding.

## Summary

Scope: how a new member joins (email + verify), gives **consent**, is placed on a
**tier**, and reaches the point of booking their first **Experience**. The task
reconciles six dated, disagreeing inputs; the reconciliation and open questions are
captured in `artifacts/docs-analysis.md`. Cross-task decisions settled here are
promoted to the project `decisions.md` so task 002 inherits them.

## Task-specific notes

- Booking mechanics themselves (capacity, waitlist, rewards) are scoped in task 002;
  this task only takes the member *to* the point of booking.
- The consent step is on the critical path and is **blocked on Legal** — see the
  blocking open question in the analysis.
